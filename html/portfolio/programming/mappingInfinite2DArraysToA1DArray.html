Introduction

This is a continuation and finalization of an old project from a few years ago which I have re-visited a multiple times, it is mainly theoretical and ended up in a place where it had no practical application for the game it was originally meant to be used with but is interesting nonetheless. It starts off with randomly generating coordinates in a 2D grid and ends up talking about cantor paring functions. Along the way I also developed some cool function benchmarking code which might end up being its own project.

Its worth mentioning here as well all the code here will be written in python (as it is what I was using at the time and as it is easy to follow) and graphs/math will be done with Desmos and Excel.


Initial Problem

I was designing a 2D videogame, the main interface was to be a grid and have some sort of treasure hunt aspects to the game. The game was mainly to practice using classes and procedural level generation in games. The grid was to have randomly distributed points of interest across it, and so I had to come up with a way of distributing them. I wanted to do it in a way which would work for any sized grid as I wasn't sure yet how big the grid would be and do so in an as efficient as possible way. The solution also needs to work quickly enough the player doesn't get bored waiting, it can't be that they leave the game as the level takes so long to generate.


Here is a summarized list of requirements :

  • Have a function which when called returns a random array of coordinates.
  • The solution should be able to work for any grid size and number of requested coordinates.

Initial Solutions

All the solutions assume a couple of things :

  • The width and height of the grid are known at runtime and will be passed in as a parameter.
  • The number of points of interest will be passed in as a parameter.
  • The grid is only in the positive region, e.g. no negative x or y coordinates (although this is possible and I will talk about this later).

> Random values

import random # Picks random cells until enough have been generated: # gridSize defines max values # requestedCells defines how many cells def getRandomCells(gridSize: list[int], requestedCells: int) -> list[list[int]]: totalCells = gridSize[0] * gridSize[1] if requestedCells >= totalCells: raise ValueError(f"requestedCells({requestedCells}) cannot be greater than total number of cells ({totalCells})") returnCells = [] while len(returnCells) < requestedCells: newCoord = [random.randint(0, gridSize[0]-1), random.randint(0, gridSize[1]-1)] if newCoord in returnCells: continue returnCells.append(newCoord) return returnCells

My initial solution was randomly picking coordinates until I had enough, this however is both inefficient and unreliable.

The function takes the width and height of the grid and then used them to find the total number of grid cells, it then loops until the number of coordinates is the same as the number of requested cells. Each iteration it gets 2 random numbers using the random library, one for x and one for y, both in the range of (0, gridSize). If the new coordinate is in the return array then it is discarded otherwise its added.

The issue with this is as its random and doesn't take into account which cells have already been selected and so the same one could be picked multiple times wasting time and resources. Theoretically the program could randomly pick the same coordinate forever and not finish.


> Random values from array

import random def getAllCoords(gridSize: list[int]) -> list[list[int]]: returnCoords = [] for x in range(0,gridSize[0]): for y in range(0, gridSize[1]): returnCoords.append([x,y]) return returnCoords def getRandomCells(gridSize: list[int], requestedCells: int) -> list[list[int]]: totalCells = gridSize[0] * gridSize[1] if requestedCells >= totalCells: raise ValueError(f"numberOfPOIs ({requestedCells}) cannot be greater than total number of cells ({totalCells})") returnCells = [] remainingCells = getAllCoords(gridSize) while len(returnCells) < requestedCells: newCoord = random.choice(remainingCells) returnCells.append(newCoord) remainingCells.remove(newCoord) return returnCells

My second solution is similar to my first one, randomly picking coordinates, this time however the coordinates are picked from an array. This method is reliable making it more efficient in a lot of scenarios, however it does come with an extra computational cost in the form of generating the remainingCells array.

The function takes the same arguments and works in a very similar way to the first solution. Here though first an array is initialized by a helper function, it contains all the grid locations and is used to prevent 2 coordinates getting randomly selected twice. Then, same as the first solution, it loops until the number of coordinates is the same as the number of requested cells, this could be replaced by a for loop though as it will finish in a known number of iterations. To select a value it uses the random library to pick a value from the remainingCells array and then add it to the return and finally remove it from the remainingCells array, this means it cannot be picked again.

This solution is good as its reliable, it doesn't have the chance of running forever, however it does have the issue of having to generate the array in the first place.

Benchmarking code, this is expanded on and edited throughout but is based of this. Full code is shared at milestones. For benchmarking purposes return values have been suspended but the code functionally is the same.
Upon initial benchmarking for the 2nd solution (see full benchmarking below) I realized the use of .remove() was very inefficient it works by using a linear search for each iteration of the loop, this means the algorithm is of \( O(N^2) \) time complexity. To improve the code we could use .pop() which is \( O(1) \), to do this we would have to find the index of the coordinate of the 1d array though.

To find its index in the array we could try to use a \( O(1) \) method, taking our knowledge of how the array is generated and using a mathematical formula, initially we can use the equation :
\[ i = (x * h) + y \] \(i : index \kern{1em} x : x\, coordinate \kern{1em} y : y\, coordinate \kern{1em} h : height\, of\, grid\)

Which maps a grid like this (note bottom left is 0,0): \[h \begin{cases} \def\arraystretch{1.5} \begin{array}{|c|c|c|}\hline 2 & 5 & 8 \\ \hline 1 & 4 & 7 \\ \hline 0 & 3 & 6 \\ \hline \end{array} \end{cases} \]
This will give us the index in the array of a coordinate, this is useful and can be used later, however by itself it will no longer work as after one coordinate has been removed from the remainingCells array, it will be out of sync :

# BEFORE [ [0,0] , [0,1] , [1,0] , [1,1] ] # using [1,0] i = (1 * 2) + 0 => i = 2 # correct # AFTER [ [0,0] , [0,1] , [1,1] ] # using [1,1] i = (1 * 2) + 1 => i = 3 # incorrect

To solve this we would have to take to account how many cells to the left (in the remainingCells array) have been removed already and use it to apply an offset. In the example above 1 cell had been removed to the left in the after example, applying an offset of -1 would have yielded the correct value. To do this however it will require finding the index of the coordinate anyway. Making it redundant in this scenario.

Given this approach isn't working we can compromise on binary search which is O(log(N)), a lot better than out O(N) from before and given the way the array is generated and handled it will always be ordered. We will have to modify the binary search to take into account the array structure but that isn't difficult, initially it should search only on the x coordinate then when the x coordinate is matching search with the y. Here it is :

def binarySearchCoords(coord : list[int], coordArray : list[list[int]]) -> int: l_pointer = 0 r_pointer = len(coordArray) -1 while l_pointer <= r_pointer: m_pointer = l_pointer + floor( (r_pointer - l_pointer) / 2) if coordArray[m_pointer][0] < coord[0]: l_pointer = m_pointer+1 elif coordArray[m_pointer][0] > coord[0]: r_pointer = m_pointer-1 else: if coordArray[m_pointer][1] < coord[1]: l_pointer = m_pointer+1 elif coordArray[m_pointer][1] > coord[1]: r_pointer = m_pointer-1 else: return m_pointer

Multiprocessing test code and binary search/array benchmarking

The solution so far works well, and the testing code works ok but it can be slow for lots of tests/solutions, so lets add multiprocessing, this will allow for the benchmarking code to run faster.

[[0, 1824028.6583372], [0.00046440004371106625, 1824028.6588016], [84.07810569996946, 1824112.7364429], [98.91097670001909, 1824127.5693139], [98.91933800000697, 1824127.5776752]]

The multiprocessing works by running tests in parallel using the multiprocessing library. The solutions themselves are still run in parallel on different procceses.

Explanation

Here is an explanation of the updated code :


It starts in main.py, first it checks if the code being run is on the main process:

if __name__ == "__main__":

It checks this in order to prevent new processes in a multi-processed test to run main when initiated and loading scripts.

It then sets up variables and the multiprocessing library for tests:

mp.freeze_support() timing = [] timing.append([0, time.perf_counter()]) tests = Tests() tests.genTests(2, 50, 0, 1000, 100) tmp = time.perf_counter() timing.append([tmp - timing[0][1], tmp]) solutions = [ {"id": "sol_01", "function": sol_01.getRandomCells}, {"id": "sol_02", "function": sol_02.getRandomCells}, {"id": "sol_03", "function": sol_03.getRandomCells} ]

Note these lines :

tests = Tests() tests.genTests(2, 50, 0, 1000, 100)

This initializes an instance of the generates a random set of tests which can be later run on the solutions.

class Tests(list): def __init_subclass__(cls): return super().__init_subclass__() # Generate random tests here def genTests(self, minGridSizeLen : int, maxGridSizeLen : int, minRequests : int, maxRequests : int, testNumb : int, replace : bool = False): if replace: self.clear() for i in range(0, testNumb): # random grid size test_gridSize = [ random.randint(minGridSizeLen, maxGridSizeLen), random.randint(minGridSizeLen, maxGridSizeLen) ] # random number of requests (capped at min of (maxRequests, number of cells in grid)) test_requests = random.randint(minRequests, min(maxRequests, test_gridSize[0]*test_gridSize[1])) self.append({ "id" : "test_"+idm.getNewID(str), "size" : test_gridSize, "request" : test_requests, })

Tests extends the list class, it adds functionality to run the elements in it as tests upon solutions passed to it. genTests() is a function it defines which takes in bounds for the types of tests you want and generates them.

Tests stores the tests as dictionaries in the format :

{ "id" : "test_1", "size" : [5, 19], "request" : 34, }

Note the values are randomized, see code for more details.

At this point we run the tests, there are multiple ways of doing it but here we will do both:

# runs tests and gets results results1 = tests.runSolutions(solutions, repeat_count=100, updates=True) tmp = time.perf_counter() timing.append([tmp - timing[0][1], tmp]) results2 = tests.runSolutionsMultiprocessed(solutions, cpu_count(), repeat_count=100, updates=True) tmp = time.perf_counter() timing.append([tmp - timing[0][1], tmp])

results1 stores the benchmark for tests run in series and results2 stores tests run with the multiprocessing approach.

First we will look at runSolutions()

def runSolutionProccessesMultiprocessed(self, solution : dict, proccesses : int, queue : mp.Queue, repeat_count : int = 10000, updates : bool = False): with mp.Pool(proccesses) as p: results = p.starmap(runSolutionOnTest, [(solution, test, repeat_count, True) for test in self]) if updates: print(f"{solution['id']} - finished") output = { "solutionID" : solution["id"], "totalTime" : sum(t for _, t in results), "times" : {id : t for id, t in results} } if updates: print(f"{solution['id']} - output generated") return output

runSolutionProccessesMultiprocessed() sets up proccessing pools and maps solution-tests tuples to the runSolutionOnTest() function on different proccesses, it then runs them all and gets the solution. It then does the same structuring as runOnSolution() and returns the results.
Now the tests have been run we can save the results.

# structures results into a dictionary data = { "dataFormatVersion" : 1.0, "tests" : tests, "results1" : results1, "results2" : results2 }

We create a dictionary with all the tests, results and a id to tell us what type of formatting we are using, we do this so that when interpreting data it wont crash if we change how the results are formatted.
